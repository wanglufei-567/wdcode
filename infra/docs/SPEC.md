## 基础设施规格

### 一、职责

`infra` 是 `wdcode.cn` 的部署控制面，负责：

- **Caddy** 公网入口和 **HTTPS**
- 域名与路径到运行时服务的路由
- 生产 **Docker Compose** 编排
- 应用镜像版本和运行参数
- 容器网络、持久化卷和健康检查
- 定向发布、验证、回滚和数据备份边界

### 二、不负责的内容

`infra` 不负责：

- 个人站页面和内容实现
- 基金业务逻辑
- 学习笔记原文维护
- 从兄弟仓库源码执行生产构建
- 在 **Git** 中保存生产密钥或业务数据

### 三、镜像接入契约

每个应用镜像必须声明：

- 不可变版本
- 容器监听端口
- 健康检查
- 必需和可选环境变量
- 持久化目录及数据语义
- 启停和回滚约束

生产编排只消费镜像，不使用兄弟仓库作为 `build.context`

### 四、当前服务

| 服务 | 容器端口 | 职责 |
|---|---:|---|
| `caddy` | `80`、`443` | 公网入口、TLS 和反向代理 |
| `personal-web` | `80` | 个人站静态资源和 **SPA** 回退 |
| `fund-web` | `80` | 基金应用网关、静态资源、**SPA** 回退和内部 API 转发 |
| `fund-api` | `5174` | 基金 API 和持久化数据访问 |

`fund-api` 使用唯一服务名，供基金 Web 网关在共享私有网络中解析

### 五、网络边界

- 只有 **Caddy** 发布宿主机 TCP `80`、TCP `443` 和 UDP `443`
- 应用服务只加入 **Docker** 私有网络
- **API** 不直接暴露公网
- 容器间通信使用稳定服务名或明确网络别名

### 六、路由

```text
wdcode.cn/*     -> personal-web:80
www.wdcode.cn/* -> https://wdcode.cn/*
fund.wdcode.cn/* -> fund-web:80
```

`fund.wdcode.cn` 的内部 `/api/*` 由基金 Web 镜像内的 **Nginx** 转发到 `fund-api:5174`

### 七、发布边界

- 个人站变化只更新 `personal-web`
- 基金 Web 变化只更新 `fund-web`
- 基金 API 变化只更新 `fund-api`
- 路由变化单独校验和重载 **Caddy**
- 数据卷变化先完成备份和兼容性验证
- 不使用全量重启代替定向部署
