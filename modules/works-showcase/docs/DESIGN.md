## 工程实践模块设计规范

### 一、设计姿态

工程实践模块采用“编辑档案”方向，像一份经过整理、可以复查的工程档案，延续个人站克制、清晰、安静的阅读气质

页面首先说明项目解决的问题和实现方式，再给出仓库、测试、运行界面与在线演示等证据，职业展示是可能产生的结果，不进入显式叙事

案例页是外部项目真值的展示投影，不复制完整 **README**、伪造运行结果，也不把个人站改造成产品营销落地页

必须避免演示优先的产品落地页、装饰性指标面板、技术档案表格堆积、终端拟态和重复英文眉题

### 二、已选方向

首个 `SQLEditor` 案例比较过三种完整方向：编辑档案、产品实证、工程剖面；第二个 `Flowlyte` 案例用于验证同一设计系统能否承载没有在线 Demo 的原生应用

最终选定“编辑档案”，保留以下设计真值：

- `/works` 使用具有真实截图和核心说明的项目预览，不退化为仓库名称列表
- 目录页与详情页必须建立清晰层级差：目录页用于选择，详情页用于展开证据和工程叙事
- 案例详情把首屏空间交给最强证据载体：可交互项目直接展示在线工作台，原生应用展示真实界面组与公开发行入口
- 正文使用案例索引与连续工程叙事，不使用同尺寸卡片网格切碎内容
- 验证记录必须同时说明验证对象、依据和结论，不使用脱离来源的大数字
- 运行链路可以编号，因为顺序本身具有信息；普通章节和工程取舍不使用装饰性编号
- 能力与未实现边界并列呈现，使用相同的信息密度和证据标准
- 在线演示存在时默认加载；没有在线 Demo 时不伪造交互，改用真实截图、可下载产物和发布记录建立证据

### 三、页面结构

#### 3.1 工程实践目录

- `/works` 只展示已经完成证据核验和案例适配的项目
- 页面开头用紧凑标题与一段说明建立模块范围，不出现功利化职业叙事或转化文案；目录首屏的视觉焦点属于具体项目，不属于模块标题
- 每个作品由对应适配目录提供预览组件，包含项目名称、核心说明、真实截图、案例入口，以及与项目交付形态一致的直接操作
- 目录页不展示“已核验”“当前收录”、项目年份或类型等缺少选择价值的元信息，验证记录进入案例详情
- 项目预览使用上下细分隔线形成连续档案，不使用悬浮卡片或统一卡片模板
- 未完成适配的仓库不进入目录

#### 3.2 案例详情

案例详情保持以下稳定骨架：

1. 返回工程实践目录
2. 项目的最强证据载体与必要外部入口
3. 可复查的验证记录
4. 能够从源码解释的运行链路
5. 能够从源码解释的关键工程取舍
6. 可验证能力与明确未实现边界

`SQLEditor` 使用默认加载的全宽在线演示，项目标题由演示应用自身呈现；`Flowlyte` 使用主窗口与菜单栏界面组成首屏证据，并提供公开 DMG 与仓库入口

桌面端正文使用 `190px` 案例索引与自适应内容列，列间距 `clamp(40px, 5vw, 72px)`；索引在视口内保持可见，窄屏退化为可横向滚动的页内导航

### 四、视觉系统

#### 4.1 继承规则

- 复用个人站的页面色、正文色、绿色信号色、中文标题字体、原生正文栈和等宽技术标签字体
- 复用全站 `4 / 6px` 圆角、`1px` 细边界和 `160ms` 减速交互
- 绿色只承担识别、状态与主要操作，不超过页面视觉面积的 `10%`
- 不建立作品模块专属品牌色、字体文件或阴影系统

#### 4.2 比例与节奏

- `/works` 内容水平内收 `30px`，移动端取消额外内收；目录抬头使用紧凑横向结构，避免延迟首个项目出现
- 作品预览按约 `1.12fr / 0.88fr` 分配左侧截图与右侧文字，间距 `clamp(42px, 6vw, 76px)`
- 在线演示已经包含项目身份时不重复展示名称和定位，文档语义标题以无障碍隐藏方式保留
- 首屏证据高度依据视口和媒介形态计算，同时完整露出案例目录或首个正文线索
- 正文章节上下间距桌面端约 `76px`，移动端约 `56px`
- 工程取舍使用连续三列表格化行：责任标签、标题、说明，不使用独立卡片

#### 4.3 图片

- 真实产品截图不得重新设计、裁掉关键交互或替换为装饰图
- 图片保持原始宽高比，使用 `1px` 深色边界和 `6px` 圆角
- 目录页图注说明截图中的当前界面状态，不重复项目标题
- 详情页截图可以作为在线演示加载占位，也可以作为无法嵌入运行时的主要界面证据

### 五、交互与响应式

- 主要按钮使用绿色实底，次要按钮使用细边界白底，按钮文案必须说明将打开什么
- 链接、按钮和页内索引必须支持 `:focus-visible`
- 不依赖浏览器滚动条或额外提示文案，使用真实案例内容在首屏底部自然建立延续感
- 目录进入案例时同步、瞬时复位滚动位置，不允许平滑滚动让新页面从旧位置回到顶部
- 支持 **View Transitions API** 时只让当前项目的目录截图向详情主证据过渡，每个项目使用唯一名称；根页面和公共页头不做交叉淡化，避免白色闪烁
- `900px` 以下首屏、作品预览和案例正文改为单列，案例索引变为横向页内导航
- `680px` 以下验证记录、工程取舍和能力边界改为单列
- `390px` 宽度不得出现页面级横向滚动，只有页内索引和必要的外部演示可以在自身容器内滚动
- 所有位移动画在 `prefers-reduced-motion: reduce` 下关闭

### 六、外部体验与发行边界

- 工程实践目录只使用经验证并压缩的真实截图，不请求外部应用
- 在线演示案例进入详情后立即创建并优先加载 `iframe`，不设置二次触发入口；`iframe` 必须有明确标题、稳定尺寸和最小权限沙箱
- 内嵌演示已经提供源码入口时，详情页不重复提供“打开在线 Demo”或 **GitHub** 入口
- 原生应用案例不模拟网页交互，使用真实运行截图、公开发行页和安装产物；安全提示、签名与公证状态必须如实说明
- 外部加载成本只发生在访问对应案例详情或主动点击外部入口时，不进入个人站首页或工程实践目录首屏
- 个人站只保存展示投影，业务源码、构建、发布和安装产物仍由对应外部仓库拥有

### 七、内容规则

- 只陈述能够从源码、测试、构建和运行界面验证的事实
- 每条验证记录包含验证对象、证据来源与结论，不把测试数、方言数或工作区数作为装饰性指标
- 技术选择必须连接到具体职责，不堆叠工具名称
- 边界与能力同等重要，不把“没有实现”隐藏在营销措辞中
- 项目发布状态、包发布状态和线上可用性分别陈述
- 中文承担主要信息，英文只用于项目名、技术名词和必要状态，不作为重复装饰标签

### 八、后续案例守门规则

- 每个外部项目拥有独立适配目录、元数据、目录预览组件和案例组件
- 新案例复用注册流程、页面节奏与证据规则，但不强制复制 `SQLEditor` 的内容章节
- 不容易在线展示的项目可以使用运行证据、架构链路或输出样例替代 Demo
- 案例内容更新应收拢在对应适配目录，不修改主应用路由实现
- UI 变更必须验证工程实践目录、案例深链接、外部链接、移动端、键盘焦点、控制台和生产构建

### 九、**AI Coding** 守门规则

- 选定设计真值不得因实现方便退化为列表卡片、指标条或动态加载模块
- 新增作品时优先扩展项目适配器，不在 `WorksRoutes` 中写项目特例
- 不为了统一案例结构，把外部仓库的完整 **README** 或业务源码复制进本模块
- 视觉修正优先复用个人站令牌，不在模块内覆写全局导航与页脚
- 修改后必须在等价桌面端与移动端状态下对照本文件和已选设计稿复查
